# Training and reproducing the model

This guide covers training a detector candidate. To *use* the detector, see
the [project README](../README.md). The detector is a fully fine-tuned
ModernBERT-base token classifier with a BIOES decoder; there is no rule layer.
All task-specific text is generated by this project's synthetic generators; no
clinical dataset is used for training.

The default model is `models/takeover-deberta-mix9c-001/step-000845`
(DeBERTa-v3-base, `deberta_mix9c_001`; previously mix5 epoch 1). Its weights are gitignored; copies are kept in the private data
repository described in [CLEANUP.md](../CLEANUP.md).

## Environment

```sh
uv venv --python 3.13
uv pip install --python .venv/bin/python -e '.[dev]'
export TIKTOKEN_CACHE_DIR="$PWD/.cache/tiktoken"
export HF_HOME="$PWD/.cache/huggingface"
```

Inference sends no text to any hosted service. On Apple silicon, set
`DEID_DEVICE=mps`; CPU is supported.

## Training a candidate

Candidates are trained by the project owner from a frozen, preflighted
protocol. `reports/takeover/mix5_001/` is the worked example:

1. Freeze each training corpus (mode `0444`) and run the sanctioned overlap
   audit, `scripts/takeover/overlap_audit_v9r3.py`, over the whole mixture.
2. Remove rows that overlap the development banks with
   `scripts/takeover/prepare_training_mixture.py` where needed.
3. Run a preflight over a pinned inventory (`preflight/run_preflight.py` in
   the run directory): input pins, tokenizer alignment, development overlap,
   duplicates and conflicting gold.
4. Write the protocol and launch script, then train with
   `scripts/takeover/train_hf.py`. It evaluates the development selection banks
   after each epoch.
5. Evaluate every candidate with `scripts/takeover/eval_bank.py` and apply the
   [GOALS.md](../GOALS.md) regression rules against the incumbent.

```sh
PYTHONPATH=src .venv/bin/python scripts/takeover/train_hf.py \
  --model-name answerdotai/ModernBERT-base \
  --resume-weights models/takeover-mbbase-mix3-001/step-003081/hf \
  --train data/TRAIN_1.jsonl data/TRAIN_2.jsonl \
  --select data/v12_validation.jsonl data/tk_train_geriatric__census1_v9clean.jsonl \
  --output models/NEW_RUN --epochs 2 --lr 2e-05 --batch-size 32 --device mps
```

The earlier Privacy-Filter adapter detector, its trainer and its rule layer
were removed on 2026-10-04. To reproduce historical adapter results, check out
commit `cbaf3af` or earlier.

## Synthetic data remediation (v11)

The [completed remediation](../reports/current_state_snapshot.md) was run with
the removed adapter detector. Its records are historical.

New development uses the [shared annotation policy](annotation-policy-v2.md)
and [remediation plan](synthetic-data-remediation.md). Legacy corpora remain
historical evidence.

The replacement generators create separate versioned files and refuse to replace
existing differing artifacts. The development generator is independently authored.
Run commands from this checkout with `PYTHONPATH=src:scripts`:

```sh
PYTHONPATH=src .venv/bin/python -m clinical_deid.data.generators.remediation --output data/NEW_train.jsonl
PYTHONPATH=src .venv/bin/python -m clinical_deid.data.generators.remediation_development --output data/NEW_validation.jsonl
PYTHONPATH=src:scripts .venv/bin/python scripts/audit_corpus_quality.py \
  --corpus train=data/NEW_train.jsonl --corpus validation=data/NEW_validation.jsonl \
  --output reports/NEW_quality.json
```

Promotion is decided by the privacy gates and regression rules in
[GOALS.md](../GOALS.md). New candidates use ModernBERT; see [AGENTS.md](../AGENTS.md).

Original experiment protocols and outputs are immutable. The retained
`reports/v11_remediation_frozen_sources/` snapshot preserves their source state.
The evaluation amendment and posthoc LOCATION repair are separate records;
new experiments should prepare new protocols and output directories with the
current source, rather than overwrite or resume a historical protocol after edits.

## Narrative and compositional generators

The new narrative generators add single-token names and places, broader role
language, contrasting identifier captions, and clinical negatives. The
compositional training bank preserves each original narrative training note's
exact PHI values and labels while varying grammar and layout. It replaces that
bank during v6 training; all 4,200 development notes stay unchanged. Training
retains each epoch and selects checkpoints using exact typed-span metrics rather
than cross-entropy alone. Additional training duration is a comparison caveat;
this experiment alone cannot establish that context composition caused a gain.

```sh
.venv/bin/python -m clinical_deid.data.generators.narrative
.venv/bin/python -m clinical_deid.data.generators.compositional
.venv/bin/python scripts/retire_final_to_development.py \
  --source data/challenge_final.jsonl --output data/retired_v4_development.jsonl
```

## Places addendum curriculum

`clinical_deid.data.generators.places` writes terse and ordinary training rows for the
[places addendum](annotation-policy-v2-places.md): real localities, care-site
abbreviations and short names, matched public-reference negatives and mixed
care/citation rows. Real names come only from pinned Census Gazetteer and CMS
Hospital General Information files plus `data/care_site_names.json`, only from
the addendum's `train` value pool, and never from the blind places bank's
hashed exclusion list.

```sh
PYTHONPATH=src .venv/bin/python -m clinical_deid.data.generators.place_sources fetch
PYTHONPATH=src .venv/bin/python -m clinical_deid.data.generators.places generate
PYTHONPATH=src .venv/bin/python -m clinical_deid.data.generators.places check
```

`check` regenerates both splits and confirms they are byte-identical to the
manifests.
