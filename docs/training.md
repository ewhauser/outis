# Training and reproducing the model

This guide covers building the adapter from source. To *use* the detector, see
the [project README](../README.md). The pretrained OpenAI Privacy Filter
backbone stays frozen; only the residual clinical adapter and BIOES NER head
are trained. All task-specific text is generated by this project's synthetic
generators; no clinical dataset is used for training.

## Environment

```sh
uv venv --python 3.13
uv pip install --python .venv/bin/python -e '.[dev]'
export TIKTOKEN_CACHE_DIR="$PWD/.cache/tiktoken"
export HF_HOME="$PWD/.cache/huggingface"
.venv/bin/python scripts/bootstrap.py
```

`scripts/bootstrap.py` downloads the base checkpoint at the revision pinned in
that script. Downloads happen only during setup; inference sends no text to any
hosted service. Training caches frozen backbone features locally so repeated
epochs are fast. On Apple silicon, set `DEID_DEVICE=mps`; CPU is supported.

## Default adapter lineage

These commands reproduce the lineage of the default `models/clinical-adapter`
checkpoint. Each stage resumes from the previous adapter with additional
synthetic corpora.

```sh
.venv/bin/python -m clinical_deid.synthetic --output data --train-count 12000 --val-count 1000
.venv/bin/python -m clinical_deid.train --epochs 16 --cache-batch-size 32 --output models/clinical-adapter-v1
.venv/bin/python -m clinical_deid.augment_synthetic generate --output data --train-count 4000 --val-count 1000
.venv/bin/python -m clinical_deid.challenge --suite development --seed 240100 --count 800 --output data/challenge_development.jsonl
.venv/bin/python scripts/prepare_development_training.py
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --resume models/clinical-adapter-v1 --output models/clinical-adapter-v2 \
  --epochs 24 --learning-rate 0.0002 --cache-batch-size 32
.venv/bin/python -m clinical_deid.context_synthetic --train-count 3000 --val-count 600
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-train data/context_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --extra-validation data/context_validation.jsonl \
  --resume models/clinical-adapter-v2 --output models/clinical-adapter-v3 \
  --epochs 20 --learning-rate 0.0001 --cache-batch-size 32
.venv/bin/python -m clinical_deid.coverage_synthetic --train-count 3000 --val-count 600
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-train data/context_train.jsonl \
  --extra-train data/coverage_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --extra-validation data/context_validation.jsonl \
  --extra-validation data/coverage_validation.jsonl \
  --resume models/clinical-adapter-v3 --output models/clinical-adapter \
  --epochs 16 --learning-rate 0.0001 --cache-batch-size 32
.venv/bin/clinical-deid serve --port 8000
```

The server refuses to start without a trained adapter in the model directory.

## Synthetic data remediation (v11)

The [completed remediation](../reports/current_state_snapshot.md) includes frozen
data, both training arms, full-Detector evaluation, a separate helper repair,
and legacy regressions. No new candidate passed the accuracy and consistency
checks or replaced the default model.

New development uses the [shared annotation policy](annotation-policy-v2.md)
and [remediation plan](synthetic-data-remediation.md). The earlier generation
and training commands above reproduce the original model lineage; they are not
the recommended inputs for a new remediation run. Legacy corpora remain
historical evidence.

The replacement generators create separate versioned files and refuse to replace
existing differing artifacts. The development generator is independently authored.
Run commands from this checkout with `PYTHONPATH=src:scripts`:

```sh
PYTHONPATH=src .venv/bin/python -m clinical_deid.remediation_synthetic --output data/NEW_train.jsonl
PYTHONPATH=src .venv/bin/python -m clinical_deid.remediation_development --output data/NEW_validation.jsonl
PYTHONPATH=src:scripts .venv/bin/python scripts/audit_corpus_quality.py \
  --corpus train=data/NEW_train.jsonl --corpus validation=data/NEW_validation.jsonl \
  --output reports/NEW_quality.json
```

`scripts/run_remediation_training.py prepare` freezes a passed quality audit,
corpora, sources, runtime, initialization and settings before its `run` command
compares fresh and continued adapter/head training. The pretrained backbone is
unchanged. The optional `overlap_owned` training policy keeps context visible
while supervising every global token once. Legacy cache behavior remains the
default for historical reproduction.

`scripts/evaluate_remediation.py` evaluates explicit development banks through
the complete Detector and saves model-only/hybrid predictions, cohort metrics,
PHI-bearing document leakage, per-label exposure and long-document batch checks.
It never launches qualification or promotes a model. Promotion is decided by
the privacy gates and regression rules in [GOALS.md](../GOALS.md). The exact
typed gates are unchanged in definition and are reported as a stretch target.
Small slices and synthetic results do not establish clinical readiness.
New candidates use ModernBERT; see [AGENTS.md](../AGENTS.md).

Original experiment protocols and outputs are immutable. The retained
`reports/v11_remediation_frozen_sources/` snapshot preserves their source state.
The evaluation amendment and posthoc LOCATION repair are separate records;
new experiments should prepare new protocols and output directories with the
current source, rather than overwrite or resume a historical protocol after edits.

## Narrative and compositional generators

The new narrative generators add single-token names and places, broader role
language, contrasting identifier captions, and clinical negatives. The
compositional training bank preserves each original narrative training note's
exact PHI values and labels while varying grammar and layout. It replaces that
bank during v6 training; all 4,200 development notes stay unchanged. Training
retains each epoch and selects checkpoints using exact typed-span metrics rather
than cross-entropy alone. Additional training duration is a comparison caveat;
this experiment alone cannot establish that context composition caused a gain.

```sh
.venv/bin/python -m clinical_deid.narrative_synthetic
.venv/bin/python -m clinical_deid.compositional_synthetic
.venv/bin/python scripts/retire_final_to_development.py \
  --source data/challenge_final.jsonl --output data/retired_v4_development.jsonl
```

## Places addendum curriculum

`places_synthetic` writes terse and ordinary training rows for the
[places addendum](annotation-policy-v2-places.md): real localities, care-site
abbreviations and short names, matched public-reference negatives and mixed
care/citation rows. Real names come only from pinned Census Gazetteer and CMS
Hospital General Information files plus `data/care_site_names.json`, only from
the addendum's `train` value pool, and never from the blind places bank's
hashed exclusion list.

```sh
PYTHONPATH=src .venv/bin/python -m clinical_deid.place_sources fetch
PYTHONPATH=src .venv/bin/python -m clinical_deid.places_synthetic generate
PYTHONPATH=src .venv/bin/python -m clinical_deid.places_synthetic check
```

`check` regenerates both splits and confirms they are byte-identical to the
manifests.
