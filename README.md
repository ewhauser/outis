# Clinical Deidentifier

A local Python library and HTTP API for clinical PHI detection, typed redaction,
and patient-consistent fictional replacement. It uses the Apache-licensed
[OpenAI Privacy Filter](https://github.com/openai/privacy-filter) encoder,
a trainable residual bidirectional clinical encoder adapter, a BIOES NER head,
and structural identifier guards. The pretrained backbone is frozen; the
clinical transformer adapter and NER head are trained locally.

All task-specific training, validation, and evaluation text is authored by this
project's synthetic generators. No clinical dataset is downloaded or licensed.
The base checkpoint is pinned in `scripts/bootstrap.py`; its own pretraining is
upstream, not generated by this project.

## Install and run

This workspace already contains the trained adapter and downloaded encoder. To
start both redaction and synthetic replacement immediately:

```sh
.venv/bin/python scripts/serve_local.py --port 8000
```

The local launcher binds to `127.0.0.1` and creates an owner-readable replacement
key once in the ignored `.cache/local-api-secret` file. It reuses that key across
restarts. A configured `DEID_SECRET` takes precedence. Preserve the key to keep
patient mappings stable; do not commit it or share it with API clients.

From the project directory:

```sh
uv venv --python 3.13
uv pip install --python .venv/bin/python -e '.[dev]'
export TIKTOKEN_CACHE_DIR="$PWD/.cache/tiktoken"
export HF_HOME="$PWD/.cache/huggingface"
.venv/bin/python scripts/bootstrap.py
.venv/bin/python -m clinical_deid.synthetic --output data --train-count 12000 --val-count 1000
.venv/bin/python -m clinical_deid.train --epochs 16 --cache-batch-size 32 --output models/clinical-adapter-v1
.venv/bin/python -m clinical_deid.augment_synthetic generate --output data --train-count 4000 --val-count 1000
.venv/bin/python -m clinical_deid.challenge --suite development --seed 240100 --count 800 --output data/challenge_development.jsonl
.venv/bin/python scripts/prepare_development_training.py
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --resume models/clinical-adapter-v1 --output models/clinical-adapter-v2 \
  --epochs 24 --learning-rate 0.0002 --cache-batch-size 32
.venv/bin/python -m clinical_deid.context_synthetic --train-count 3000 --val-count 600
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-train data/context_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --extra-validation data/context_validation.jsonl \
  --resume models/clinical-adapter-v2 --output models/clinical-adapter-v3 \
  --epochs 20 --learning-rate 0.0001 --cache-batch-size 32
.venv/bin/python -m clinical_deid.coverage_synthetic --train-count 3000 --val-count 600
.venv/bin/python -m clinical_deid.train \
  --extra-train data/development_training.jsonl \
  --extra-train data/augmentation_train.jsonl \
  --extra-train data/context_train.jsonl \
  --extra-train data/coverage_train.jsonl \
  --extra-validation data/augmentation_validation.jsonl \
  --extra-validation data/context_validation.jsonl \
  --extra-validation data/coverage_validation.jsonl \
  --resume models/clinical-adapter-v3 --output models/clinical-adapter \
  --epochs 16 --learning-rate 0.0001 --cache-batch-size 32
.venv/bin/clinical-deid serve --port 8000
```

The trained adapter lives in `models/clinical-adapter`. A trained model must
exist before API startup; a missing checkpoint fails startup. On Apple Silicon,
use `DEID_DEVICE=mps` when needed; CPU is supported. No text is transmitted to
OpenAI or another hosted inference service. Downloads occur only at setup.
Training caches frozen backbone features locally to make iterations efficient.

The HTTP API binds to loopback by default, with interactive documentation at
`http://127.0.0.1:8000/docs` and an OpenAPI schema at `/openapi.json`.

```sh
curl http://127.0.0.1:8000/v1/deidentify \
  -H 'Content-Type: application/json' \
  -d '{"text":"Patient Mara Calder, DOB 1974-06-13. Creatinine 1.2 mg/dL.","mode":"redact"}'
```

`POST /v1/batch` accepts `{"items":[...requests...]}`. There are at most 16
requests and 100,000 total characters per batch. Responses include transformed
text, original **character offsets** of detected entities, entity types,
replacement strings, model/rule confidence scores, warnings, and a model version.
Response metadata contains no original PHI, patient anchor, date offset, or key.
Scores are model probabilities or rule scores, not calibrated safety estimates.

The default API uses the hybrid detector. NER reads the original clinical text;
structural extractors then scan that same complete text and merge their matches
with the learned spans. An email does not need a successful NER prediction to
be detected. The email recognizer supports ASCII aliases and punctuation,
Unicode mailbox text and domains, punycode domains, quoted mailbox names, and
IP address literals while preserving original character offsets. Regression
tests force NER to return no PHI and verify both redaction and synthetic
replacement through the public Python API. Obfuscated forms such as
`alice [at] example [dot] org` remain outside this deterministic grammar.
`backend="model"` is available for evaluating NER separately and skips the
structural extractors.

## Consistent synthetic replacements

Set `DEID_SECRET` to a secret with at least 32 bytes and keep it stable. Synthetic
requests also require a stable `patient_id`; it anchors date shifts across notes.
This anchor is exact and case-sensitive, including whitespace. Reuse the same
opaque identifier for the patient in every request.
Rotate the secret when a new mapping universe is desired. Independent secrets
produce independent mappings. Example startup:

```sh
export DEID_SECRET="$(.venv/bin/python -c 'import secrets; print(secrets.token_urlsafe(48))')"
.venv/bin/clinical-deid serve
```

```json
{
  "text": "Mara Calder was admitted on 2024-02-28 and discharged on 2024-03-02. Creatinine 1.2 mg/dL.",
  "mode": "synthetic",
  "patient_id": "internal-patient-42"
}
```

All detected, supported exact dates for a patient share a nonzero shift. Calendar arithmetic
preserves event order, intervals, and leap days. A caller can explicitly provide
`date_shift_days` for a study-wide patient mapping, but must keep it consistent
for that patient. Incomplete or unsupported dates are redacted with warnings
instead of inventing precision. Numeric dates use month/day/year when ambiguous
and emit a warning; an initial value above 12 establishes day/month/year.
Year-first dates, dotted numeric dates, hyphenated English month names, and ISO date-times are also
supported. Date-times retain the original time of day and timezone text.
Date shifting changes calendar/seasonal context even when intervals are preserved.

Names and identifiers are replaced deterministically. Unambiguous first/last
name aliases within a note follow a detected full name. Standalone aliases
across different notes cannot be linked reliably without a full identity.
Synthetic facilities retain only whitelisted generic setting and specialty
terms, such as hospice, rehabilitation hospital, pediatric clinic, dialysis
unit, or infusion center. Identifying names and unknown terms are replaced.
Contacts use reserved fictional domains/phone ranges. Ages above 89 are
bucketed to `90+`; other ages, diagnoses, medications, doses, labs, vitals,
relative durations, and clinical narrative remain outside replacements unless
detected as PHI. The replacement engine preserves every character outside
detected spans. Fictional identities may coincidentally resemble real people;
they do not establish anonymity or resistance to reidentification.

Python API:

```python
from clinical_deid import Deidentifier

deid = Deidentifier("models/clinical-adapter", secret=b"application-secret-at-least-32-bytes")
result = deid.deidentify("Mara Calder was seen on 2024-02-28.", mode="redact")
synthetic = deid.deidentify(
    "Mara Calder was seen on 2024-02-28.",
    mode="synthetic", patient_id="internal-patient-42",
)
print(result["text"])
```

## Evaluation

The predeclared 99% target is exact typed PHI-span precision, recall, and F1,
with per-type recall, character recall, and a Wilson recall lower bound also
checked. Ordinary token accuracy is excluded. Model-only and hybrid results
are reported separately. See [evaluation protocol](reports/evaluation_protocol.md).
Document leak-free rate is reported alongside entity metrics.

The initial frozen final test contained 1,200 synthetic notes and 14,121 PHI
spans. **The 99% qualification target has not been met.** Results from that
first one-shot final evaluation were:

| Detector | Exact precision | Exact recall | Exact F1 |
|---|---:|---:|---:|
| Trained encoder and NER | 96.18% | 95.68% | 95.93% |
| Hybrid encoder, NER and clinical guards | 97.39% | 97.28% | 97.34% |

Hybrid PHI-character recall is 99.87%; 97.25% of final documents are leak-free.
The separate 3,200-note checkpoint-selection validation scored 99.82% F1, which
did not carry over to the final test. Full final metrics, per-type recall and
unchanged model/source/corpus hashes are recorded in
[final qualification](reports/final_v4_qualification.json) and the
[detector freeze](reports/detector_freeze.json). Its failures subsequently guided
decoder and clinical guard fixes, so the corpus was explicitly retired into
`data/retired_v4_development.jsonl`. Subsequent results on it are development
diagnostics.

The independently authored v5 qualification bank then exposed a larger
generalization gap in the v7 adapter and guards. Its frozen, one-shot evaluation
covered 2,160 notes and 14,112 PHI spans:

| Detector | Exact precision | Exact recall | Exact F1 |
|---|---:|---:|---:|
| Trained encoder and NER | 68.73% | 80.97% | 74.35% |
| Hybrid encoder, NER and clinical guards | 73.63% | 86.95% | 79.74% |

Hybrid PHI-character recall was 98.10%; 74.03% of documents were leak-free.
The [immutable qualification report](reports/blind_v5_qualification.json)
records the failed gates and frozen inputs. Before inspecting its failures,
that bank was retired into `data/retired_blind_v5_development.jsonl` for
validation only. The v8 pass adds broader invented clinical contexts and
negative examples, spelled-out age handling, compound care settings and
identifier-field grammar. A separately authored v6 qualification bank remains
sealed until development selection is complete. **The 99% target remains unmet.**

The latest completed full-detector development check uses the v9 epoch 8
candidate and repaired contact/name boundaries on 7,860 declared development
notes. Reapplying the current helpers to its saved actual neural predictions
scores 98.42% exact precision, 99.05% recall and 98.73% F1; NAME recall
is 95.63%, PHI-character recall is 99.82%, and 95.80% of documents are leak-free.
All 4,606 gold EMAIL spans are exact matches, with one extra model prediction.
The [saved development replay](reports/v9_epoch8_commit_hybrid.json)
and [repair delta](reports/v9_post_contact_identity_delta.json) pin the actual
neural outputs and helper sources. These figures are development evidence.

The completed matched comparison adds 2,000 authored nominal-alias training notes
and 500 separately reported development notes. Its two runs use identical
starting weights, corpora, seed and optimizer settings, with singleton
NAME/LOCATION loss weights of 1 and 4. The
[predeclared protocol](reports/training_v10_protocol.json) records 44,800
training and 8,360 development notes. Both runs completed eight epochs and
verified their frozen inputs. Control checkpoint ranking is complete; weighted
ranking and full-detector candidate verification remain pending. Earlier cohorts remain separately
reported; new examples cannot conceal regressions in them. The default model
artifact remains the original v4 adapter while later candidates are evaluated.
See [current snapshot](reports/current_state_snapshot.md) for validation and
the remaining work.

The new narrative generators add single-token names and places, broader role
language, contrasting identifier captions, and clinical negatives. The
compositional training bank preserves each original narrative training note's
exact PHI values and labels while varying grammar and layout. It replaces that
bank during v6 training; all 4,200 development notes stay unchanged. Training
retains each epoch and selects checkpoints using exact typed-span metrics rather
than cross-entropy alone. Additional training duration is a comparison caveat;
this experiment alone cannot establish that context composition caused a gain.

```sh
.venv/bin/python -m clinical_deid.narrative_synthetic
.venv/bin/python -m clinical_deid.compositional_synthetic
.venv/bin/python scripts/retire_final_to_development.py \
  --source data/challenge_final.jsonl --output data/retired_v4_development.jsonl
```

```sh
.venv/bin/python -m clinical_deid.challenge --suite development --seed 240100 --count 800 --output data/challenge_development.jsonl
.venv/bin/python -m clinical_deid.evaluate --data data/challenge_development.jsonl --model-dir models/clinical-adapter --backend hybrid --output reports/development_hybrid.json
.venv/bin/python -m pytest -q
```

Final results and model/corpus hashes are saved under `reports/` after the model
and guards are frozen. Synthetic scores establish performance only on these
generators. They do not establish 99% accuracy on real clinical records. English
plain text is the first-pass scope; scanned images, multilingual coverage,
rare identifying narratives, and unseen institutional formats need separate
evaluation. Fourteen text entity types are supported: NAME, DATE, ADDRESS,
PHONE, EMAIL, MRN, SSN, ACCOUNT, ID, URL, IP, AGE, LOCATION, FACILITY. This is
not a claim of complete regulatory deidentification.

The initial model missed the development gate. Its results are retained in
`reports/development_v1_model.json` and `reports/development_v1_hybrid.json`.
The independently authored development corpus was then explicitly converted
into training data in `data/development_training.jsonl`; its subsequent scores
are training diagnostics. Dense independently authored augmentation adds new
identity vocabularies and clinical negatives. Final qualification uses the
untouched final challenge, with different clinical families and context wording.
An additional authored context corpus broadens administrative geography, age
phrasing, and tightly delimited contacts based on adversarial development feedback.
Broader coverage adds clinical roles, OCR-style text headers, diverse name styles,
care settings, identifier taxonomy, and clinical hard negatives. Validation remains
separate from training; its results are checkpoint-selection diagnostics.
The challenge suites share a synthetic value-construction vocabulary, so their
results establish template generalization within this synthetic benchmark;
they do not establish generalization to real institutions or all unseen identities.

## Repeatable HTML performance report

Build a self-contained page from the saved quality and timing reports:

```sh
.venv/bin/python scripts/build_report.py \
  --config reports/pipeline_report_config.json \
  --output reports/pipeline_report.html
```

Open the resulting HTML in a browser. It includes quality comparisons, per-label
recall, evaluation gates, recorded detection timing, and source hashes. The
checked-in config selects the v7 candidate and its historical blind v5 results;
it does not automatically select the latest model. Edit the config to select
new evaluation reports. No model inference or corpus access is performed.
See [report configuration and metric definitions](docs/html-reports.md).

## Operational controls

Request bodies and source PHI are not logged by the application. Validation and
runtime errors return sanitized messages, and responses use `Cache-Control:
no-store`. Set `DEID_API_KEY` for `X-API-Key` authentication. The CLI requires it
when binding beyond loopback. Configure TLS and network access controls in
your deployment; downstream proxies and caller logs must follow your data
handling policy. `GET /health` checks process liveness; `/ready` verifies a
loaded model and reports whether synthetic mode has a configured secret.
